# 验收报告

对照 [target.md](../target.md) 第十五节「最终验收清单」逐项给出状态与证据。
状态只有三种：**通过**（有可复现的验证方式）、**部分**（已实现但验证不完整）、**未完成**。

## 一、功能验收

| 项目 | 状态 | 证据 |
| --- | --- | --- |
| 用户注册、登录和鉴权正常 | 通过 | e2e 第 1 组（注册/重复注册 409/登录/无 token 401/错误密码 401） |
| 文件夹管理正常 | 通过 | e2e 第 2、9 组（创建、重名 409、递归删除） |
| 小文件上传和下载正常 | 通过 | e2e 第 3、4 组（单片上传、下载 sha256 一致） |
| 大文件分片上传和恢复正常 | 通过 | e2e 第 3 组（分片上传、进度、缺失分片、长度校验）；多分片路径由 `scripts/e2e` 的 `splitParts` 覆盖（>8MiB 时自动多片） |
| 文件分享与撤销正常 | 通过 | e2e 第 6 组（密码、次数、撤销、内容一致） |
| 文件版本管理正常 | 通过 | e2e 第 5 组（版本列表、回滚幂等）+ `file_versions` 事务实现 |
| 删除和对象清理行为明确 | 通过 | e2e 第 8 组（幂等删除、配额归还）+ 后台 GC + `tools/reconcile` |

| --- | --- | --- |
| 关键操作具备幂等性 | 通过 | 幂等键三处：`idempotencyKey`、`uploadId`、`request_id`；e2e 验证了重复初始化 / 重复完成 / 重复删除 |

## 六、结论

**当前状态：可运行的完整业务闭环 + 可验证的工程质量。**

- 15 项功能/安全验收全部通过；
- 3 项"部分"都有明确的缺口说明与补齐路径（重启演练、并发压测、全容器部署验证）；
- 1 项"未完成"是性能基线——这是刻意留白的，因为编一个数字比没有数字更糟。

下一步优先级：性能基线 → K8s 演练 → 配额对账自动化 → Web 前端（见 `docs/roadmap.md`）。
